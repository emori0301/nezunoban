# models 担当 申し送り

`assets/models/*.glb`(50 個)と `assets/textures/*.png`(56 枚)を使う側への依頼と、
残っている問題。生成物の一覧とプレビューは `docs/previews/contact_sheet.png` /
`anim_sheet.png` を見てください。再生成は `bash tools/blender/build_all.sh`。

共通の約束: 単位はメートル、Y-up、原点は接地面の中心。
キャラクターは Blender の -Y 正面で作ってあるので、**Godot では -Z が正面**です
(Godot のキャラクタの既定の前方と一致します)。

---

## level への依頼

### 棺の小窓

`coffin.glb` は 2 つの MeshInstance3D を持ちます。

| ノード名 | 中身 |
|---|---|
| `coffin` | 棺本体と蓋。小窓の位置は**穴が開いている** |
| `Window` | 小窓の板 |

**`Window` を `visible = false` にすると小窓が開いた状態**になり、中が見えます。
蓋がずれた演出には `coffin_lid_open.glb`(蓋と小窓枠が +X へ 10cm ずれた版)を
別プレハブとして差し替えてください。棺の頭側は +X です。

### 扉

`door_wood` `door_steel` は**扉板のみ**で、枠は入っていません。
原点が蝶番の下端、戸先が +X。原点で Y 軸回転させれば開閉します。
扉板の寸法は木製 0.84 × 2.00 × 0.16、スチール 0.86 × 2.00 × 0.10。

`window_frame` は引き違いのアルミサッシで、窓台の下端が原点です。
床からの取り付け高さ込みで z=0.90 から始まる形にしてあるので、**床に置けばそのまま腰高窓**になります。
(扉・掲示板などと違い、これだけ取り付け高さを内蔵しています)

### 壁に付けるもの

いずれも**原点は物体の下端中央**で、取り付け高さは入っていません。level 側で持ち上げてください。

| モデル | 推奨する床からの高さ | 寸法 (X×Y×Z) |
|---|---|---|
| `wall_clock` | 1.90 m | 0.31 × 0.30 × 0.06 |
| `notice_board` | 1.05 m | 0.92 × 0.66 × 0.03 |
| `breaker_box` | 1.40 m | 0.59 × 0.32 × 0.37(扉が開いた状態) |

### 自販機の発光

`vending_machine` の前面は別マテリアル **`Panel`** です。
昼夜どちらでも破綻しないよう `emission_strength` を 0.30 と控えめにしてあります。
夜の駐車場で光らせるなら、level 側で `emission_energy` を上げてください。

```gdscript
var m := panel_surface_material as StandardMaterial3D
m.emission_energy_multiplier = 3.0
```

### そのほかの自発光マテリアル

暗転や異変の演出で強度を触れるように、名前を付けてあります。

| モデル | マテリアル名 | 既定の強さ |
|---|---|---|
| `candle_stand` | `Flame` | 4.0 |
| `incense_stand` | `Ember`(線香の火種) | 3.0 |
| `coil_incense` | `CoilEmber` | 3.0 |
| `lantern` | `LanternPaper`(提灯の紙) | 0.9 |
| `monitor_crt` | `Screen` / `MonLed` | 0.8 / 3.0 |
| `tv_crt` | `Screen` | 0.6 |
| `freezer_chest` | `FreezerLed` | 2.0 |
| `hearse` | `HeadLight` / `TailLight` | 1.2 / 1.0 |

線香とロウソクの火は**モデルに含まれています**。消えた状態を作るときは、
該当マテリアルの `emission_energy` を 0 にするか、炎のメッシュを別途隠す実装にしてください
(現状 `Flame` と `Ember` は本体メッシュと同じ MeshInstance3D のサーフェスなので、
表示切り替えではなく emission で消すのが簡単です)。

### 床・壁のテクスチャ

13 枚はすべてタイル可能です。継ぎ目が出ないことは `docs/previews/_tex_tiled.png`
(2×2 で並べたもの)で確認済み。

| 用途 | ファイル |
|---|---|
| 事務所・受付ホール・廊下・式場の床 | `floor_lino` |
| 控室(和室)の床 | `tatami`(縁付き 1 畳。上下端が縁なので、畳の長手方向に合わせて貼る) |
| バックヤード・湯灌室の床 | `concrete` |
| 駐車場・外周 | `asphalt` |
| トイレ・湯灌室の壁 | `tile_white` |
| 屋内の壁 | `wall_plaster`(黄ばんだ白壁) |
| 腰板・控室の壁 | `wall_wood`(縦 4 枚の羽目板) |
| 天井 | `ceiling_tile`(穴あきボード。2×2 枚ぶんの目地入り) |
| 障子 | `shoji`(組子 縦 3 × 横 4) |

`ceiling_tile` が 1.2 m 角に 1 枚です。

## systems への依頼

### 小窓越しの顔

`body_face.glb` はマテリアル **`Face`** を 1 つだけ持つ平たい板(0.40 × 0.30 m)です。
顔の**頭頂が +X**(棺の頭側 = 小窓のある側)を向いています。棺の中、小窓の真下に置いてください。

`albedo_texture` を差し替えることで顔の状態が変わります。

| テクスチャ | 台本上の使いどころ |
|---|---|
| `body_face_calm` | 既定。目も口も閉じている |
| `body_face_mouth` | 01:00 のドライアイス交換(顔①: 口がわずかに開いている) |
| `body_face_eyes` | 00:30 で息子に小窓を開けさせた後(以降ずっと目が開いている) |
| `body_face_turned` | 03:40(顔②: 顔がこちらを向いている)。猫が棺をまたいだ後にも |

### 遺影

`iei_frame.glb` の写真面はマテリアル **`Photo`**(既定 `iei_photo`)です。
遺影エンドでは `iei_photo_player`(暗く潰れて誰か分からない人物写真)に差し替えてください。

### 電話

`phone.glb` の受話器は別メッシュ **`Handset`** です。取る/置くの演出に使えます。
本体と受話器は別 MeshInstance3D なので、`Handset` だけ動かせます。

### そのほか

- `coffin` の内側には白布を敷いた底と暗い内壁が入っているので、小窓を開けても
  「向こう側が透けて見える」ことはありません。
- `dry_ice_box` は蓋が少しずれて載った状態です。閉じた状態が要るなら言ってください。
- `incense_box` は蓋がずれて中の線香が見える状態、`matches` は中箱が少し出た状態です。

## npc への依頼

### 目の自発光

`cat` と `kasha` はどちらもマテリアル名 **`Eyes`** が目です。

| モデル | 色 | 既定の強さ |
|---|---|---|
| `cat` | 黄(1.0, 0.92, 0.35) | 3.2 |
| `kasha` | 赤(1.0, 0.06, 0.03) | 5.0 |

異変度が上がったら `emission_energy` を上げる、暗い廊下で目だけ先に見せる、といった
演出に使えます。火車の本体はほぼ黒(`kasha_skin`)なので、暗所では目だけが見えます。

### アニメーション

`AnimationPlayer` に以下の名前で入っています。30fps、すべてループ前提の作り
(`rise` だけは 1 回再生)。

| モデル | アニメ名 | 長さ | 中身 |
|---|---|---|---|
| `cat` | `idle` | 96F (3.2s) | 呼吸、尻尾の揺れ、ときどき首を振る |
| | `walk` | 24F (0.8s) | 対角の脚が同時に出るトロット |
| | `sit` | 72F (2.4s) | 座り姿勢を保ち、尻尾と首だけ動く |
| `kasha` | `idle` | 96F (3.2s) | ほとんど動かず、頭と尾だけ不気味に揺れる |
| | `crawl` | 40F (1.3s) | 長い四肢を交互に前へ出して這う。背骨がうねる |
| `npc_boss` `npc_son` `npc_granddaughter` | `idle` | 90F (3.0s) | 呼吸で上下 + わずかな重心移動 |
| | `walk` | 30F (1.0s) | 1 周期。**その場歩き**なので移動は Godot 側で |
| `body_risen` | `rise` | 60F (2.0s) | 寝た状態から上体を起こす |

`body_risen` は**寝た姿勢が rest ポーズ**です。棺の中に寝かせて置き、`rise` を 1 回
再生すると上体が起き上がります。起き上がった先では自分の足元(+Y 方向)を向きます。

- 顔の差し替え(`body_face_calm` → `_mouth` → `_eyes` / `_turned`)は台本の時刻と

## 追加分(2026-09-23)

### `hanging_robe.glb` — 湯灌室に吊るす白装束

原点は**床**。ハンガーのフックの先端が **+Y 2.00 m**(実測 2.009、針金の太さぶん)。
モデル全体の Y は 0.58〜2.00、幅 0.87(袖を広げた状態)、奥行 0.20。174 頂点。

ボーンは 3 本、マテリアルは `RobeCloth`(白布)と `HangerWire`(ハンガーの針金)。

| ボーン | 役割 |
|---|---|
| `Hook` | ハンガーと針金。**動かない**。装束が落ちてもこれは残る |
| `RobeTop` | 肩〜腰。揺れと落下はこのボーンが持つ |
| `RobeBottom` | 腰〜裾。揺れが遅れて伝わる |

| アニメ | 長さ | 中身 |
|---|---|---|
| `sway` | 121F / **4.0 秒ちょうど・ループ** | ゆっくり前後左右に揺れる。振れ幅は肩で 2〜3 度 |
| `drop` | 46F / **1.5 秒・1 回** | ハンガーから滑り落ち、前に倒れて床で崩れる。ハンガーは空のまま残る |

`drop` の終わりで装束は原点から **Godot の +Z 方向に約 1.2 m** 伸びた位置に横たわります
(襟の前面も +Z 側)。壁際に置くときは **+Z 側に 1.3 m** ほど空けてください。
台本の「入るたびに揺れ方が変わる」は `sway` の `speed_scale` と再生開始位置
(`seek()`)を変えるだけで作れます。最後に床へ落とすときだけ `drop` を 1 回再生してください。

### `paw_print.png` — 濡れた猫の足跡(64×64, RGBA)

暗い水の色(ほぼ黒に青みがかったグレー)。縁に水が溜まって濃くなる描き方にしてあります。
**画像の上(V が大きい側)が進行方向**の指球側です。廊下 → 式場 へ並べるときは、
進行方向へ向けて回転させてください。四辺 2px はアルファ 0 なので、重ねても縁が出ません。

Godot では `Decal` ノードの `texture_albedo` に入れるのが簡単です
(床が平らなので `Decal` で十分。サイズの目安は 0.12 m 角)。
左右の前足を交互に、進行方向へ 0.25〜0.35 m 間隔、左右に 0.06 m ほど振ると自然です。

### `handprint.png` — 小窓の内側の手形(128×128, RGBA)

皮脂で曇ったような白っぽい手形。**指先が画像の上(V が大きい側)**。
掌の中央はわずかに薄く(浮いて接地していない)、指と掌の縁が濃く出ます。
アルファは最大 0.55 程度なので、下地の木目やガラスが透けます。

棺の小窓の内側に貼る想定です。`coffin.glb` の小窓の開口は
X 0.48〜0.80、Y(高さ)0.42 の面なので、0.16 m 角くらいで置くと手のひらの大きさになります。
「内側から触った跡」なので、**小窓の板 `Window` ではなく、その下(棺の内側)に置いてください**。

どちらも Godot 側で `format=RGBA8`、アルファ付きで読み込めることを確認済みです。
プレビューは `docs/previews/decals.png`(下地に重ねた状態と、市松の上でのアルファ単体)。

## 追加分その2(2026-09-23)

### `white_cloth.png` を布に見えるよう作り直しました

**棺の内張り・祭壇の白幕・シーツ・白装束・芳名帳の白布が全部これを使っているので、
level / systems 側の変更は不要です。glb を作り直したので再インポートだけしてください。**

前の絵は 2 次元ノイズの等高線で皺を描いていたため、大理石の脈に見えていました。
作り直した版は、

- 皺を**一方向に流れる平行な帯**にした(位置だけをもう片方の軸のノイズで揺らす)
- **織り目(縦糸・横糸)を実際に描いた**。これが無いと布に見えない
- 畳んだ折り目(まっすぐな線)を数本入れた

という作りです。同じ理屈で `futon_cloth` の皺も直してあります。

**UV スケールの注意**: 織り目は 256px に 56 本なので、**1 タイルを 0.3〜0.6 m 程度に
貼らないと布に見えません**。祭壇は 1.2 → 3.2 に上げて直りました。
大きな面に貼るときは `uvscale` を 3 以上にしてください(1.0 前後だと
皺の帯が巨大な染みに見えます)。

### `futon.glb` を作り直しました

291 頂点、1.05 × 0.30 × 2.00(**-Z 側が頭**。枕と襟の折り返しがある方)。

### 棺の小窓は本当に貫通しています

`Window` を非表示にすると、小窓の穴から中の `body_face` が見えます。
`docs/previews/coffin_window.png` が証拠です(左から 小窓閉/小窓開/覗き込み/蓋 60 度開き)。

確認のときに**本体が中を塞いでいた不具合を 2 つ直しました**。どちらも

2. 側面の飾り帯が全面を覆う板だったので、z=0.31 で中を塞いでいた
   → 周囲 4 本の帯にした

**同じ理由で `freezer_chest` と `safe` の中も空洞にしました。** 蓋/扉を開けたときに
中身が見えます。冷凍庫は霜のついた内張り(`FreezerInner`)、金庫は暗い内装と棚板
(`SafeInner`)が入っています。ドライアイスや台帳は systems 側で中に置いてください。

- 金庫の庫内: X -0.18..0.18、Y 0.085..0.53、Z -0.19..0.19(棚板が Y=0.30 にあります)

## 追加分その6(2026-09-23)— キャラクターの向きを -Z に統一

### npc へ: `model_yaw_offset_deg` は **全キャラ 0 にしてください**

`cat.glb` だけが逆、という報告でしたが、**実測したら 6 体すべてが +Z 正面**でした。
猫だけ目立ったのは、猫が歩いて移動するので向きの間違いが画に出たためだと思います。
NPC は立ち止まっていることが多いので気付きにくかったはずです。

原因は座標変換の取り違えです。glTF は `gltf_z = -blender_y` なので、
**Blender で -Y 正面に組むと Godot では +Z 正面**になります。
これを -Z だと思い込んでいました。

直す前の実測値(顔・目・鼻のマテリアルの重心 z):

| モデル | 修正前 | 修正後 |
|---|---|---|
| `cat` | +0.311 | **-0.311** |
| `kasha` | +0.655 | **-0.655** |
| `npc_boss` | +0.075 | **-0.075** |
| `npc_son` | +0.076 | **-0.076** |
| `npc_granddaughter` | +0.071 | **-0.071** |
| `body_risen` | +0.628 | **-0.628** |

出力前にアーマチュアを Z 軸 180 度回すようにしました
(`build_chars.py` の `face_godot_forward()`)。メッシュはアーマチュアの子なので
一緒に回り、アニメはボーン空間なので影響しません。`walk` の脚の振りも確認済みです。

**6 体すべてが Godot の -Z 正面になったので、npc 側の `model_yaw_offset_deg` は
すべて 0 にしてください。** 猫だけでなく NPC 3 体と火車・故人も対象です。

### ついでに直した書き間違い

同じ取り違えで、向きのある小物の説明も逆に書いていました。実測して直しました。

| モデル | 正しい向き(Godot) |
|---|---|
| `toilet` | 鉢(正面)が **+Z**、タンク(背面)が **-Z**。壁には -Z 側を寄せる |
| `futon` | 枕(頭側)が **-Z** |
| `hanging_robe` | 襟の前面が **+Z**。`drop` では **+Z 方向**へ倒れる |

`door_wood` / `door_steel` の「戸先が +X」、`body_face` の「頭頂が +X」は
X 軸なので変換の影響を受けません。そのままで正しいです。

## MPFB2(人物 3 体の素体)— 最終版

### 出典とライセンス

| もの | 出典 | ライセンス |
|---|---|---|
| MPFB2 本体 | https://github.com/makehumancommunity/mpfb2 (v2.0.17) | GPL-3.0-or-later |
| MakeHuman のベースメッシュ・ターゲット(素体の形) | http://www.makehumancommunity.org/ | **CC0** |
| 生成した `npc_*.glb` | — | CC0 の素体由来なので配布に制限なし |

MPFB2 本体は **ビルド時のツール**で、ゲームには同梱されません。出力される
メッシュは CC0 のベースメッシュとターゲットから作られるので、GPL は波及しません。

### 再生成の手順

```bash
# 1 回だけ: Blender に MPFB2 を入れる(約 45MB)
curl -sS -L -o /tmp/mpfb.zip \
  "https://extensions.blender.org/download/sha256:4f0a879d64a39bf646fbf5f53601ac678855da329d650617dca5737548239a87/add-on-mpfb-v2.0.17.zip"
blender --background --python-expr \
  'import bpy; bpy.ops.extensions.package_install_files(filepath="/tmp/mpfb.zip", repo="user_default", enable_on_install=True)'

# 人物 3 体
blender --background --python tools/blender/build_humans_mpfb.py
blender --background --python tools/blender/build_humans_mpfb.py -- npc_boss   # 1 体だけ
```

`build_all.sh` は MPFB の有無を見て、入っていなければこの工程を飛ばします。
最新版の URL は `https://extensions.blender.org/api/v1/extensions/` の
`id == "mpfb"` の `archive_url` で取れます。

### 落とし穴(全部はまりました)

1. **`create_human(feet_on_ground=True)` はメッシュだけ持ち上げ、リグを動かさない。**
   0.8m ズレる。`False` で作り、足を床に乗せるのはアーマチュアの location で。
2. **マクロはシェイプキーとして乗る。** 素の頂点座標から身長は測れない。
   一度作って `bake_targets` し、実身長を測って生成スケールを直して作り直す。
3. **`add_builtin_rig` の骨は素体のスケールに完全には追従しない**(頭の骨は
   身長を変えても同じ位置に来る)。**服の着丈はメッシュの部位から測る。**
4. **リグを付けたあとに頂点を動かすと、アーマチュアモディファイアが引き戻す。**
   寸法合わせはリグを付ける前に済ませる。
5. **素体は A ポーズ。** 自作アニメは腕が真下の前提なので `straighten_rest()` で
   正立させてレストポーズに焼く。`pose_bone.matrix` に代入するときは
   **骨の頭を中心に回す**(そのまま掛けるとアーマチュア原点まわりの回転になる)。
6. **頂点グループには MakeHuman 独自のもの(`body` `scalp` `lips` …)が混ざる。**
   重み 1.0 で入っていて骨の判定を潰すので、**ボーン名だけに絞る**
   (`bone_group_map()`)。これを忘れると髪や服の面が 1 枚も選ばれない。
7. **髪のキャップは Decimate の前に作る。** 間引いた後の頭は頂点が足りず、
   キャップが頭頂の小さな斑になる。

### 作り方の要点

- 服は別の筒ではなく **素体メッシュを複製 → 部位で切る → Solidify(1.2cm 外側)**。
  ウェイトは複製で引き継がれるので、形も動きも必ず体に沿う。
- スカートと上着の裾は **別メッシュのロフト(円錐台)**。
  Solidify 後のリムを掴んで伸ばす方式は、リムの頂点が拾えず効かない。
  上端 `pelvis`、下端 `thigh_l`/`thigh_r` 0.5/0.5 の手動ウェイト。
- リグは MPFB の `game_engine`(53 ボーン)。自作アニメは `GE` の対応表で
  ボーン名を読み替えて当てる。`idle`/`walk`/`sit`/`sit_floor`/`sleep` の 5 種。
- 髪テクスチャは **細い毛筋の低コントラストノイズ**。太い筋を強く乗せて減色すると
  ブロック状の迷彩に見える。白髪は面ではなく筋として混ぜる。
- 顔テクスチャの上端 24px(出力 128px で 12px)を髪色へグラデーションで馴染ませる。
  ここを地肌のままにすると髪との境に肌色の帯が出る。
